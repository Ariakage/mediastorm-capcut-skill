# 项目接入检查

证据标记：`[课程]` 为课程归纳，`[推论]` 为工程化整理，`[工具]` 为本机工具事实。

## 检查顺序

1. `[课程][02 03:02–03:40]` 检查实际编码和可解码性，不以扩展名替代判断。
2. `[课程][07 05:03–07:53]` 记录源分辨率、帧率、时长、声道与采样率；导出决策后移到交付阶段。
3. `[课程][04 01:25–02:50]` 按项目组织素材，按用途拆分小样/成片、A-roll/B-roll、包装、图片、音效、BGM。
4. `[课程][16 01:01–03:05]` 保留相机原文件名，使用目录和清单补充语义，避免失去追溯关系。
5. `[课程][07 02:21–05:03]` 迁移后执行重链接与重开检查，不假设整体移动目录必然恢复所有引用。
6. `[课程][02 03:40–04:17]` 先定位缓存、后台任务、预览负担，再决定是否代理。
7. `[课程][03 09:32–10:29]` 代理用于降低预览负担；最终输出前确认使用原始素材。

## 接入门

- 原件未改动且哈希或来源记录可追溯。
- 所有必需媒体可解码、可定位、已重链接。
- 源帧率、分辨率、音轨、时长和关键时间范围已记录。
- 代理与原始文件关系明确。
- 私有媒体不会被自动上传或同步。
- 草稿为隔离副本或用户明确授权的目标。

## 失败与停止条件

- 媒体只存在于未知云端或失效路径。
- 源文件为可变网络链接，无法追溯版本。
- 用户要求清理缓存但范围、文件类型和备份未确认。
- 素材只够低清代理，却承诺高分辨率成片。
- 需要云同步或外部模型，但没有授权。

## capcut-cli 边界

- 用 `capcut projects`、`info`、`materials`、`tracks`、`segments`、`diagnose` 做只读诊断。
- 写入前取对应 `describe --command` 契约；命令级 `mutates` 不代表具体选项的副作用。
- 不以裸 `capcut describe` 为机器契约来源；本机 0.31.1 曾观察到 stdout 截断。
