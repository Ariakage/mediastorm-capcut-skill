## 一、本课定位

这是一节**桌面版剪映的 AI 工具操作课（DLC 加餐课）**，不是理论课，也不是成片拆解。全片在剪映桌面界面内演示两件事：

1. **智能粗剪**：用一段约 40 分钟的长口播和一段约 12 分半的访谈，演示“把剪辑要求写成提示词，让模型直接在时间线上切出片段”。窗口里没有时间线，只有“输入文稿”和大模型选项，核心是提示词。
2. **AI 文生视频**：把上一环节筛出的梦境文本送进剪映内置的视频生成面板，设置模型、画幅、时长、分辨率，看到积分消耗提示后生成片段；再用剪映的文本模型把口语稿改写成更专业的视频提示词，二次生成更稳定的梦境镜头。

演示中反复出现的立场是：先懂剪辑逻辑，再用 AI；AI 输出不稳定，提示词和参数决定结果；生成画面不能替代剪辑判断。课程用“梦境”专题作为贯穿案例，结尾用约十几秒宣传影视飓风的 AI 实战课，属于课程推广，不是剪辑方法。

本课能提供的可迁移信息主要是**操作链路与界面结构**；画面质量、听感、生成稳定性没有经过连续音画或实际工具复现验收。

### 7. 从文本到视频的两条链路

**链路 A：长口播粗剪**

长口播 → 智能粗剪窗口 → 选“原声剪辑” → 粘贴逐字稿 + 策略指令 → 开始粗剪 → 主轨得到首尾相接的短片段 → 放大时间线微调 → 叠加 B-roll / 包装。

**链路 B：访谈筛选 → 文本 → 生成**

访谈素材 → 新时间线 → 智能粗剪 → 输入“只保留梦境描述段落”的筛选提示词 → 开始粗剪 → 只留下梦境片段 → 智能字幕识别 → 导出 TXT（UTF-8）→ 复制一段描述到视频生成面板 → 设模型/画幅/时长/分辨率 → 看积分后生成 → 若效果粗糙，用“添加口播稿 + 豆包 Pro”改写提示词 → 复制回视频面板 → 二次生成 → 生成片段回到时间线。

## 五、可提炼的剪辑知识

### 智能粗剪

- [画面] 智能粗剪是一个**独立窗口**：没有时间线、没有素材片段列表，只有一个“输入文稿”框和“配音解说 / 原声剪辑”选项。它把“找气口、读文稿、逐行勾选”的工作替换成“写剪辑要求”。
- [画面] 入口在时间线右键菜单的“智能粗剪[限免]”，与“智能剪口播[限免]”并列；找不到时课程要求先更新到最新版本。
- [画面] 勾选“原声剪辑”是为了让人声素材更好被模型识别；课程字幕的解释是“确保 AI 的大模型能够更好地适配口播素材的纯人声类型”。
- [画面] 同一个工具可以承担三类任务：
  1. 长口播粗剪（去废词、去重复、保留最佳 take）；
  2. 访谈主题筛选（只保留“梦境场景/视觉画面/具体意象”相关段落）；
  3. 已剪时间线上的定向删除（删掉所有“绿色产品”口播）。
- [画面] 结果质量与提示词具体程度直接相关：03:42 的短提示词得到竖屏综艺片段；04:24 的长提示词明确“对比语义、处理忘词结巴、比较情绪与流畅度、自动切除失败 take、只留最好一段”，结果片段密度高且首尾相接。
- [推论] 提示词至少应写清四件事：**保留什么、删除什么、按什么标准判断、切开后怎么处理（是否吸附贴合）**。课程用 04:24 与 07:52 两个例子反向说明了这一点：写了“吸附贴合”的访谈任务，结果片段连续；只写“找出并删掉”的绿色产品任务，删除后留下空隙。
- [待验] “自动切除失败的 Take”是否真的按情绪/流畅度比较，还是主要按文本重复和停顿判断；画面只能看到结果片段，不能看到模型内部依据。绿色产品删除后是否应该自动合拢，取决于提示词还是工具默认行为，也需要在剪映界面实测。

### 字幕、文本与导出

- [画面] 智能字幕的源语言可设为“自动检测语言”，并可开启“自定义词汇识别”[新增]；翻译语言、智能划重点、智能去水词在演示时为灰色。
- [画面] 字幕可以导出为 TXT，文字编码可选 Unicode / UTF-8；导出对话框同时提供音频 MP3 320 kbps / 48 kHz 和 GIF 320P 选项。
- [推论] “筛选后的片段 → 智能字幕 → 导出 TXT”是把视频素材转成**干净文本素材**的实用链路：既保留时间顺序，又去掉无关闲聊，适合后续做提示词、文案或二次检索。
- [待验] 导出的 TXT 是否只包含字幕文本、是否带时间码、是否按片段顺序合并，画面只看到导出设置，没有看到导出后的文件内容。

### AI 文生视频

- [画面] 视频生成面板的核心输入是“参考 + 提示词 + 模式 + 模型 + 画幅 + 时长 + 分辨率”。课程演示的默认模型是 **Seedance 2.0 Fast**，模式 **全能参考**，画幅 **与草稿一致**，时长 **10**，分辨率 **720p**。
- [画面] 模型下拉明确列出三档：Fast（效果更优、音视图文均可参考、暂不支持人脸）、Mini（速度更快、性价比高、暂不支持人脸）、1.0（价格更低、仅支持单图参考）。这三档描述是录课界面文字，不代表当前版本。
- [画面] 生成按钮上方会显示本次消耗积分；画面在不同参数下读到 200、1070、856。课程字幕明确提醒“AI 生成是有对应的代价和成本的，那就是积分的消耗”“生成质量越高，消耗的积分越多”。
- [画面] 可以先在时间线上生成“待生成视频”占位片段，预留位置和时长，生成完成后再回看结果。占位片段在生成中显示“生成中60.0% 00:00:04:00”。
- [画面] 生成结果会直接落到时间线，和实拍素材同轨；13:56–13:58 可以看到生成片段与“梦境采访”实拍片段并排。
- [旧笔记] 旧笔记已指出 00:10:05 画面确认案例选择 `Seedance 2.0 Fast`，并提醒该名称只作为录课界面证据、当前可用性和积分不能据此保证；本轮 10:04–10:07 的画面与这一判断一致。
- [字幕] 课程把“文生视频”的适用场景概括为：缺 B-roll / 空镜头时补一段；需要复杂特效转场时用提示词直接做；只要脑中有想法，时间线上就“不再有任何无法实现的镜头”。
- [字幕] 但课程同时强调：AI 工具使用和剪辑调色一样，不是“按一下按钮就能一劳永逸的玄学”，需要长期练习、驾驭参数、写好提示词；“剪辑依然是不可或缺的能力”。
- [推论] 这节 DLC 的隐含工作流是：**人类负责判断与结构，AI 负责机械粗剪和生成素材**。智能粗剪解决“看不完的素材”，文生视频解决“拍不到/拍不起的镜头”，但两者都要回到时间线里由人审看、挑选、拼接。
- [待验] 生成片段是否真的与提示词中的动作、场景、镜头运动一致；课程只展示了少量成功结果，没有展示失败率、重试次数、积分总消耗，也没有展示生成片段的音轨和帧率。

### 提示词优化

- [画面] 直接把口播逐字稿贴进视频生成框，生成结果“挺粗糙的，甚至有点呆板”；课程把原因归结为“大白话里面有太多和画面无关的废话，AI 很难理解”。
- [画面] 剪映的“智能文本 → 添加口播稿”可以把口播稿交给文本模型（默认豆包 Pro）改写；输入方式是自然语言，例如要求“改写成更适合发给 AI 生成视频的提示词，画面要超现实主义风格，始终贴合梦境天马行空、虚无缥缈的感觉”。
- [画面] 文本模型下拉还有 DeepSeek-R1；课程选择保持默认豆包 Pro，并说明“这个模型主要是帮你处理文字、改写文案”，与视频生成模型不同。
- [画面] 改写后的提示词明显更具体：包含“超现实主义风格的哈利波特背景梦境视频”、人物关系、动作、场景转换、镜头/画面气质等；二次生成得到城堡跑动、餐车、卡牌等更稳定的镜头。
- [推论] 可复用的提示词优化步骤：
  1. 先拿到干净的口播/访谈文本；
  2. 明确要生成的是“视频提示词”，而不是继续讲故事；
  3. 指定风格、主体、场景、动作、镜头气质；
  4. 用文本模型压缩、重构，去掉口语废话；
  5. 复制回视频面板，保持参数一致再生成；
  6. 审看结果，必要时重写提示词或调参数，而不是盲目重试。
- [待验] 文本模型改写是否会篡改原意、是否会把否定句改成肯定句、是否会遗漏关键主体；课程只展示了一个成功案例，没有做对照实验。

### 方法与边界

- [字幕] 课程把“先学剪辑逻辑、再学 AI 工具”作为明确立场：不了解剪辑逻辑，会觉得 AI 效果不如意、难用；AI 产出不固定，且有学习成本。
- [字幕] 课程把 AI 生成画面称为“自媒体创作的冰山一角”，并明确“剪辑依然是不可或缺的能力”。
- [推论] 对本项目 Skill 的启示：AI 工具应作为“粗剪/素材补充”的一个可选分支，而不是替代剪辑判断的主流程；任何生成结果都要经过人眼审看，不能把生成画面当作实拍证据。
- [待验] 课程演示的是桌面版剪映的某个版本；当前版本的入口、模型、积分、分辨率档位、是否支持人脸参考，都需要以用户本机实际界面为准。
